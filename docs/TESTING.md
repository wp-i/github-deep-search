# 测试标准

## 目标

测试用于证明当前 `0.1.0` 产品契约，而不是保护旧实现。旧测试、旧场景和历史运行结果
都不是新开发的验收标准。

每次运行测试前，先确认断言仍符合 `PRODUCT_CONTRACT.md`。如果测试和当前契约冲突，
应删除或重写测试，不能为了旧断言向运行时增加兼容补丁。

## 测试分层

### 确定性单元测试

默认测试不访问网络，使用协议级 fake 或 mock 验证：

- 输入长度、语言、凭据和不可变原始输入；
- LLM 输出结构、双语查询和无降级语义；
- 公开仓库限制、查询执行、候选合并和独立性；
- 仓库有效性、证据来源和能力声明边界；
- 全局排序输出结构与排序原则；
- 报告只投影分析结果；
- 六阶段事件、单任务、重连、取消和超时；
- Provider 错误分类和密钥脱敏；
- Web 状态、SSE、复制和手动 Markdown 下载。

测试可以使用中立的合成输入验证结构和关系，但不得把样例业务词、仓库名单或预期结果
写入运行时，也不得通过固定同义词表让测试通过。

### Provider 契约测试

GitHub 测试至少验证：

- 必须使用非空测试 Token；
- 不存在匿名降级；
- 401、403、429、网络和单查询错误具有明确语义；
- 只接受公开仓库；
- README、目录、文件、Release 和仓库关系映射正确。

LLM 测试至少验证：

- OpenAI-compatible Chat Completions 请求；
- 输入、输出 token 统计；
- 错误响应脱敏；
- Markdown JSON 提取和结构失败；
- 不进行语义重采样或字面搜索降级。

### Web 集成测试

使用 fake Provider 运行完整六阶段，验证：

- 同一时间只有一个活动任务；
- SSE 只发送真实事件；
- 页面断开后可以重新连接；
- 用户可以取消；
- 完成结果仅在内存中存在；
- 报告不会写入项目目录；
- 页面只能主动复制或下载 Markdown；
- 失败不会暴露部分报告或凭据。

### 真实 Provider 验证

只有以下情况需要真实验证：

- 解析、查询规划或双语发现语义发生变化；
- 候选发现、证据选择或证据解释发生变化；
- 全局分析、排序提示或评分契约发生变化；
- 出现确定性测试无法判断的真实关联度问题；
- 发布前验证。

普通 UI、序列化、样式、类型整理和不改变行为的重构不要求额外调用独立评审 LLM。

## 执行顺序

1. 运行受影响的确定性测试。
2. 运行完整确定性回归。
3. 编译检查。
4. 如触发真实验证，只运行一个最小案例并复用已确认的上游数据。
5. 首次真实失败后立即停止后续调用，定位所属阶段。
6. 只有结果存在无法由正常回归裁决的语义争议时，才使用独立上下文评审 LLM。

不得通过重复采样、切换模型或追加提示把失败结果刷成成功。只有明确的短暂网络或 Provider
故障可以进行有限重试，失败仍需记录在当次调试上下文中。

## 阶段验收

### 清理基线

- Web 和 Docker 可以启动。
- 页面只显示开发状态和凭据状态。
- 搜索明确不可用，不调用旧引擎。
- CLI、MCP、Tavily、旧评审和旧评估产物不存在。
- Provider、配置和 Web 基础测试通过。

### 输入与运行管理

- 真实六阶段状态模型存在。
- 单任务、取消、600 秒超时、断线重连和内存生命周期通过测试。

### 解析

- 原始输入不变。
- 结构包含完整需求、约束、合理解释、双语查询和证据目标。
- 无效 LLM 输出明确失败。

### 发现

- 只搜索公开 GitHub 仓库。
- LLM 候选经过 GitHub 验证。
- 单查询失败警告与整体失败语义不同。

### 证据

- 有效项目和无效仓库边界通过测试。
- 每项公开能力可以回到仓库证据。
- fork、镜像和同源项目不能重复占位。

### 分析与报告

- 候选在共享上下文中全局比较。
- 成功结果严格包含三个独立项目和一个关联度分数。
- 报告不重排、不重新评分、不增加分析结论。
- 公开只显示 token 用量。

## 产物规则

测试缓存、真实报告、trace、截图和 Provider 响应都不得作为长期仓库资产提交。真实验证
只在当前开发上下文中检查，完成后清理。任何保存的临时内容都必须脱敏。
