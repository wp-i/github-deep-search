## 已确认且不再重复讨论的产品方向

- 产品接收一次自然语言输入，单向执行，不向用户追问，由 LLM 对合理解释作出最终断言。
- 输入最多 2000 个字符；支持中文、英文和混合输入。只要存在中文，报告使用自然中文并
  保留技术名词。
- 唯一用户入口是 Web；不提供搜索 CLI 或 MCP。Docker 保留用于本地运行。
- GitHub 是唯一发现和证据数据源，只访问公开仓库，并且必须使用 GitHub Token；不允许
  匿名降级，不使用 Tavily 或通用网页搜索。
- LLM 只承诺 OpenAI-compatible Chat Completions。解析结果结构无效时失败，不进行第二次
  语义修复，也不退化为字面关键词搜索。
- 产品执行真实的“输入 → 解析 → 发现 → 证据 → 分析 → 报告”六阶段。证据不足时允许在
  预算内进行受限补充发现，但不能无限循环。
- 成功结果固定为三个真实、公开、有效且相互独立的项目；不足三个时整次运行失败，不填充
  无关、重复或无证据仓库。
- 排序的唯一核心是项目与用户完整输入的关联度。核心功能覆盖优先于开箱即用程度；用户
  明确约束产生高权重影响但不作硬排除；最近代码推送时间是重要的次级因素。
- 免费、移动端、MCP 等只是用户可能提出的普通约束，不建立任何特定业务规则。Stars 和
  Fork 数默认不参与排序，除非用户明确要求流行度。
- 对用户只展示一个 0～100 整数关联度分数，且只用于本次运行内部排序。证据用于支撑评分，
  不产生第二套证据分或报告分。
- 报告只投影分析结论，不生成市场机会、建设建议或决策简报。服务端不保存报告；用户只可
  在浏览器中复制或主动下载 Markdown。
- 每个进程只允许一个活动任务，不排队、不并发。断开页面不会取消任务，支持重新连接、
  主动取消和默认 600 秒全局超时。结果仅在内存保留到下一次运行或进程重启。
- 公开用量只包含 LLM 输入 token、输出 token 和总 token。
- 当前处于开发测试阶段，不发布。开发阶段成本优先；只有语义核心变化才做最小真实
  Provider 验证，不例行增加独立评审 LLM。发布阶段再以结果质量优先。

完整细则以 [产品契约](PRODUCT_CONTRACT.md) 为准。以上内容不是后续实现可自行调整的默认
参数，而是已经完成确认的产品决定。

## 后续执行顺序

后续对话应按以下顺序推进，每一阶段先建立契约模型和确定性测试，再实现唯一行为所有者：

1. **输入与运行管理**：实现输入验证、报告语言、六阶段状态、单任务、SSE、重连、取消、
   600 秒超时和内存生命周期；使用可控假流水线完成 Web 集成测试。
2. **解析**：定义 LLM 输出结构、结构校验、合理解释、约束、双语查询和证据目标；无效结构
   明确失败，不增加字面兜底。
3. **发现**：实现认证 GitHub 搜索、候选合并、公开仓库复验、查询级警告和整体失败语义。
4. **证据**：实现仓库资格验证、README/目录/源码/配置采集、能力证据状态、同源去重和一次
   受限补充发现。
5. **分析与报告**：实现共享上下文中的唯一排序、严格三个项目、单一关联度，以及不改变
   上游判断的 Markdown 投影和浏览器交付。
6. **整体回归**：完成确定性六阶段回归和浏览器验收；涉及语义核心时才运行一个最小真实
   Provider 案例，首次失败立即停止并定位所属阶段。

不得为了尽快恢复搜索按钮而跳过阶段所有权、用旧引擎拼接流程，或在报告层补偿解析、证据
与排序问题。

## 下一轮决策状态

截至本记录，已发现的核心产品矛盾都已经完成确认，下一轮开始前没有悬而未决的产品决策。
数据类命名、内部事件字段、模块私有 helper 和测试 fake 的组织方式属于实现细节，可以在
不改变上述契约的前提下按最小耦合原则确定。

只有出现下列情况时，后续执行必须暂停并再次向用户确认：

- 两条已确认产品规则在真实案例中产生无法同时满足的冲突；
- 需要新增数据源、用户交互、服务端持久化、多用户并发、自动下载或其他超出契约的能力；
- 需要改变固定三个结果、唯一关联度、功能覆盖优先、公开仓库或强约束非硬过滤等核心规则；
- 真实 Provider 限制使当前六阶段在既定成本或时间内无法实现，并且调整会改变用户结果；
- 准备进入发布阶段，需要重新决定默认模型、真实验证强度、质量门槛和发布运维策略。

如果仅遇到普通实现缺陷，应依据 `AGENTS.md` 定位最早错误阶段并做最小修正，不需要重新
讨论已经确认的产品方向。
