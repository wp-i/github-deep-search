# Win10 悬浮桌面任务看板开发简报

文档状态：可用于新开发对话
最后更新：2026-07-30（Asia/Shanghai）
暂定项目代号：Floating Task Board（正式名称待定）

## 1. 文档用途

这是一份独立产品开发交接文档。它将已经确认的产品需求、交互重点、
MVP 边界、技术路线、现有项目复用结论和验收标准固定下来，供新的开发
对话直接使用。

这不是 `github-deepSearch` 的功能扩展。`github-deepSearch` 只承担了前期
项目检索与证据分析；新的桌面工具应创建在独立目录或独立仓库中，不应把
产品代码加入 `github_deep_search` 包。

## 2. 一句话产品定义

一个仅面向 Windows 10 的桌宠式悬浮任务看板：用户可以在桌面小窗中直接
新增、编辑和拖拽任务，也可以把同一窗口自然展开成更舒适的完整看板与任务
详情编辑界面。

它不是 Jira 的桌面复制品，而是把最常用的个人看板动作压缩到一个随手可用、
视觉精致、几乎没有学习成本的桌面小工具中。

## 3. 已确认的三个产品支柱

### 3.1 桌面悬浮，操作便捷

- 启动后默认出现在桌面右下角。
- 默认保持可见，支持置顶、折叠、移动和调整尺寸。
- 用户无需打开浏览器或切换到传统管理软件即可处理任务。
- 小窗本身就是可操作的看板，不是只读提醒器或入口图标。
- 移动窗口与拖动任务必须有明确、互不冲突的交互区域。

### 3.2 只做 Windows 10

- MVP 不考虑 macOS、Linux、移动端或网页端。
- 不为跨平台抽象牺牲 Windows 桌面行为、性能或视觉完成度。
- 安装、开机启动、系统托盘、窗口置顶和位置恢复均按 Windows 10 设计。
- 默认中文界面；MVP 不建设国际化体系。

### 3.3 样式与交互是核心功能

- 视觉设计不是开发完成后的装饰阶段，而是产品能力的一部分。
- 卡片拖拽、状态反馈、展开/折叠和直接编辑必须自然、稳定、可预期。
- 产品应像桌宠或精致桌面组件，而不是缩小后的后台管理页面。
- 宁可减少功能，也不能用粗糙表格、默认控件堆叠或割裂的配置弹窗代替核心体验。

## 4. 用户核心场景

### 场景 A：快速记录

用户正在处理其他工作，直接在右下角悬浮看板中点击快速新增，输入标题并按
Enter，任务立即进入“待办”。整个操作不需要打开完整窗口。

### 场景 B：快速推进

用户把任务卡片从“待办”拖到“进行中”，或从“进行中”拖到“已完成”。
状态即时保存，视觉反馈明确，重新启动后顺序与状态不丢失。

### 场景 C：补充任务详情

用户点击任务卡片或展开按钮，悬浮窗口从右下角自然展开。用户可以在更大的
界面中编辑任务描述、优先级和截止时间，然后收回小窗继续工作。

### 场景 D：长期常驻

应用随 Windows 启动，默认恢复到用户上次使用的位置、尺寸和展开状态。
关闭主界面时可退到系统托盘，用户可以从托盘恢复或彻底退出。

## 5. MVP 功能范围

### 5.1 P0：必须完成

#### 悬浮窗口

- 无传统标题栏或使用完全自定义标题栏。
- 默认右下角显示，并保证窗口不会落到屏幕可见区域之外。
- 支持置顶开关、窗口移动、有限尺寸调整、折叠和展开。
- 记住窗口位置、尺寸和置顶偏好。
- 独立的窗口拖动把手；在卡片区域按下鼠标不会误移动整个窗口。

#### 基础看板

- 固定三列：待办、进行中、已完成。
- 支持直接新增、编辑、删除任务。
- 支持卡片跨列拖拽改变状态。
- 支持同列拖拽排序。
- 拖动时显示原位置、目标位置和可放置状态。
- 空列必须有清晰的空状态与新增入口。

#### 快速编辑

- 悬浮态可以直接编辑任务标题。
- 支持点击或快捷入口新增任务。
- 常用操作不依赖右键菜单。
- 保存采用即时或自动保存，不要求用户反复点击“应用”。

#### 展开模式

- 优先采用同一窗口从右下角展开，而不是另外弹出传统配置窗口。
- 展开后显示更宽的三列看板和任务详情编辑区。
- 展开/收起前后使用同一份实时状态，不重新加载、不丢失焦点中的合法编辑。
- 展开界面仍然属于桌面工具，不进入浏览器或外部网页。

#### 任务详情

- 必填：标题。
- 可选：描述、优先级、截止时间。
- 系统字段：状态、列内顺序、创建时间、更新时间。
- MVP 不加入评论、附件、子任务、协作人和复杂标签体系。

#### 本地运行

- 数据默认只保存在本机，不要求登录和网络连接。
- 修改后自动持久化，异常退出后已成功保存的数据可恢复。
- 支持系统托盘、开机启动开关和明确的“彻底退出”。
- 提供可安装或可直接分发的 Windows 可执行产物。

### 5.2 P1：MVP 稳定后再做

- 一套浅色主题或有限主题切换。
- 全局快捷键呼出/隐藏。
- 任务搜索与简单过滤。
- 数据导入、导出和手动备份。
- 列名称或列数量的有限配置。
- 完成任务的批量归档。

### 5.3 明确不在当前范围

- macOS、Linux、移动端和浏览器版本。
- 多用户、团队、权限、评论和实时协作。
- 云同步、账号体系和服务端。
- AI、自动拆解任务、聊天助手。
- Jira/Trello API 集成。
- 截图、Markdown 编辑器、CRM、邮件提醒和复杂自动化。
- 插件市场和高度可配置工作流。

## 6. 关键交互规范

### 6.1 窗口移动与卡片拖拽

- 只有顶部拖动区域或明确把手可以移动窗口。
- 从卡片主体拖动时只移动任务卡片。
- 从卡片文字编辑区域拖动选择文本时不得触发卡片拖拽。
- 需要设置合理的拖动距离阈值，避免单击被误判为拖拽。
- 拖拽失败或取消后，任务必须返回原位置且数据不变。

### 6.2 卡片直接编辑

- 单击选中，双击或显式编辑按钮进入标题编辑，具体方式在原型阶段确定。
- Enter 保存，Esc 取消；失焦行为必须统一。
- 保存失败时保留用户输入并显示可恢复提示。
- 已完成卡片保持可读，不使用过低对比度隐藏内容。

### 6.3 展开与收起

- 展开按钮在悬浮态始终可发现。
- 展开以右下角为视觉锚点，避免窗口突然跳到无关位置。
- 动画应短、顺滑且可中断，不阻塞用户输入。
- 收起时保留当前看板滚动位置和选中任务。
- 如果任务详情正在编辑，收起前应自动保存合法内容；存在校验错误时明确提示。

### 6.4 状态反馈

- 拖动目标列、保存状态、危险删除和不可用操作都有视觉反馈。
- 不使用频繁弹窗确认普通操作。
- 删除可以使用短时撤销；彻底清空等不可恢复操作才要求确认。
- 动画服务于位置与状态理解，不添加无意义的持续动效。

## 7. 视觉设计要求

- 先确定设计语言和高保真交互稿，再批量实现页面。
- 悬浮态保持轻量、紧凑，但不能缩小到无法直接操作。
- 使用清晰的层级、留白、圆角、阴影和状态色，不直接采用浏览器默认样式。
- 三列状态应容易分辨，但避免大面积高饱和色块。
- 卡片的 hover、pressed、dragging、drop-target、editing 和 completed 状态均需设计。
- 字号、点击区域和对比度要适合长时间桌面常驻。
- 第一版只做一套完成度高的主题，不用多主题掩盖基础设计不足。
- 视觉验收必须使用真实 Win10 截图或录屏，不能只检查 DOM、组件树或单元测试。

## 8. 建议数据模型

### Board

- `id`
- `title`
- `createdAt`
- `updatedAt`

MVP 可以只有一个默认 Board，但数据结构不要把单看板写死到每个 UI 组件中。

### Column

- `id`
- `title`
- `order`
- `kind`：`todo`、`doing`、`done`

### Task

- `id`
- `boardId`
- `columnId`
- `title`
- `description`
- `priority`
- `dueAt`
- `order`
- `createdAt`
- `updatedAt`

### Preferences

- 窗口位置与尺寸。
- 是否置顶。
- 是否开机启动。
- 上次展开状态。
- 主题和动画偏好预留，但 MVP 可固定默认值。

数据层应通过明确接口服务于悬浮态和展开态，UI 组件不得分别维护两套任务真相。

## 9. 技术路线建议

### 9.1 首选：Tauri 2 + React/TypeScript

选择理由：

- 样式、动画、卡片布局和看板拖拽接近成熟网页交互的开发方式。
- Tauri 的窗口配置提供 `decorations`、`alwaysOnTop`、`transparent`、
  `dragDropEnabled` 等桌面窗口能力，适合无边框悬浮工具。
- Windows 使用 Microsoft Edge WebView2；Tauri 官方说明 Windows 10 1803
  及以后通常已经包含 WebView2，Windows 安装器也提供 bootstrapper、离线
  installer 和固定 runtime 等分发方式。
- 相比把整个既有 Tkinter 工具改造成高交互看板，新建 Web UI 更符合本产品
  “样式和交互优先”的目标。

官方依据：

- [Tauri Windows prerequisites](https://v2.tauri.app/start/prerequisites/)
- [Tauri WindowConfig](https://v2.tauri.app/reference/config/#windowconfig)
- [Tauri Windows installer 与 WebView2 分发](https://v2.tauri.app/distribute/windows-installer/)

建议结构：

```text
src/
  app/                 应用启动、路由与全局状态
  board/               看板领域模型、排序和状态迁移
  components/          通用视觉组件
  features/
    floating-board/    悬浮态
    expanded-board/    展开态
    task-editor/       任务详情
    preferences/       少量设置
  persistence/         前端持久化适配接口
src-tauri/
  src/                 窗口、托盘、自启动、单实例和本地存储命令
  capabilities/        最小权限配置
```

不建议在 React 组件内直接调用所有 Tauri API。窗口控制、本地持久化和任务
领域状态应有清晰边界，便于测试和未来更换实现。

### 9.2 备选：WPF

如果阶段 0 原型证明 WebView2 透明窗口、焦点、拖动命中或安装体验无法达到
要求，则切换到 WPF。WPF 是 Windows-only UI 技术，具有样式、模板、动画、
数据绑定和正式拖放基础设施，适合作为本项目的原生备选。

- [WPF overview](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/)
- [WPF drag and drop](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/drag-and-drop)

不要同时维护 Tauri 和 WPF 两套实现。阶段 0 结束时必须选定一个技术栈，
删除被放弃的原型路径。

## 10. 阶段 0：技术与交互原型门槛

正式开发前先完成一个不接业务数据库的薄原型，只验证最高风险部分：

1. Win10 无边框、置顶、透明背景窗口。
2. 默认右下角定位和屏幕边界约束。
3. 窗口拖动区域与卡片拖拽区域互不冲突。
4. 三列中的 6–10 张模拟卡片可以跨列拖动和排序。
5. 小窗可以平滑展开、收起，并保持卡片状态。
6. 打包后的程序能在干净 Win10 环境启动。
7. WebView2 缺失时安装行为明确且可恢复。

只有这些条件通过后才建设完整持久化和任务编辑。若原型失败，定位失败边界，
比较修复成本后决定调整 Tauri 方案或切换 WPF；不要在失败实现上堆补丁。

## 12. 开发阶段

### 阶段 0：高风险原型

- 验证窗口、拖拽、展开动画、Win10 打包和 WebView2 边界。
- 输出可运行原型、Win10 截图/录屏、问题记录和最终技术选型决定。

### 阶段 1：核心 MVP

- 实现三列看板、任务 CRUD、直接编辑、拖拽排序和本地持久化。
- 实现悬浮态、展开态、托盘、位置恢复和开机启动。
- 建立领域状态和持久化测试。

### 阶段 2：视觉与交互收口

- 根据真实 Win10 使用过程打磨视觉层级、动效、焦点、键盘行为和异常反馈。
- 覆盖空状态、长标题、大量任务、快速连续拖动和窗口边界。
- 完成高保真截图/录屏对照评审。

### 阶段 3：发布验证

- 生成安装包或明确的便携分发包。
- 在干净 Win10 环境验证安装、启动、WebView2、托盘、自启动、升级和卸载。
- 完成许可证清单、数据存储位置说明和最小用户说明。

## 13. MVP 验收矩阵

| 维度 | 必须通过的行为 |
| --- | --- |
| 启动与定位 | 首次启动出现在右下角；不会超出可见屏幕；后续恢复上次位置 |
| 桌面悬浮 | 无传统窗口负担；置顶开关有效；窗口可移动、缩放、折叠和展开 |
| 快速新增 | 在悬浮态输入标题并确认后立即出现任务卡片且完成持久化 |
| 直接编辑 | 标题可就地编辑；Enter/Esc/失焦规则一致；编辑不会误触发拖拽 |
| 看板拖拽 | 可跨列改变状态、同列排序；目标反馈清晰；取消后数据不变 |
| 展开体验 | 展开/收起流畅；同一任务状态和选中项保持；不是割裂的新配置窗口 |
| 任务详情 | 展开态可编辑描述、优先级、截止时间并自动保存 |
| 数据可靠性 | 正常退出、托盘隐藏和重新启动后任务、顺序与设置保持 |
| Win10 集成 | 托盘、开机启动、彻底退出和单实例行为明确 |
| 视觉完成度 | 真实 Win10 截图/录屏通过人工评审；所有关键交互状态均有设计 |
| 安装交付 | 干净 Win10 环境可以安装并启动；WebView2 缺失路径经过验证 |
| 范围控制 | 没有账号、云同步、AI、跨平台或团队协作等非 MVP 功能 |

## 14. Definition of Done

MVP 只有在以下条件全部满足时才算完成：

- 阶段 0 选型门槛通过且不存在双技术栈残留。
- P0 功能全部通过自动测试和真实 Win10 人工操作验证。
- 卡片拖拽、直接编辑、展开/收起均有真实截图或录屏证据。
- 应用可离线处理全部核心任务操作。
- 数据在重启后保持，且没有悬浮态/展开态双状态源。
- 打包产物在干净 Win10 环境通过安装与启动验证。
- 所有复制的第三方代码均有许可证与来源记录。
- 没有尚未裁决的 P0/P1 缺陷。
